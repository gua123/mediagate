## mediagate 0.1.35

### 先说结论：**你的服务器没问题**，而且我用你的凭据在开发机上把它验通了

我拿 `.toolchain/real-server.properties` 里的账号密码，对**你截图里那个地址**跑了我们 App 会发的那条请求：

| 请求 | 结果 |
| --- | --- |
| `PROPFIND http://vpn.gua233.top:20005/`（匿名） | **401** + `WWW-Authenticate: Basic realm="SYNO_WebDAV Storage"` |
| 同一条 + 账号密码 | **207 Multi-Status** ✅ |

⇒ 地址、端口、账号密码、**以及我们发的那条 PROPFIND 请求本身**，全都是对的；
服务器是群晖的 WebDAV、用的是 Basic 认证（我们客户端也是 Basic，对得上）。
（顺带发现：本机存的测试配置里 WAN 地址还是旧端口 **25005**，那个端口现在连不上——你截图里的 20005 才是现行的。）

所以问题在"**App 实际发出去/收回来的是什么**"这一环，而这件事以前看不出来。

### 这一版让探针把话说清楚

1. 失败信息现在带上 **请求的 URL + 响应状态行 + 响应体开头一小段**（群晖/Apache 的报错页往往直接写着原因）；
2. 探针**自己跟随重定向**了（以前 OkHttp 的自动跟随会把 PROPFIND 降级成 GET，所以历史上我们干脆不跟随——
   代价是碰到 301 就只报一句 "HTTP 301"；现在按原方法重发，并保留认证头）；
3. 片段做了脱敏（URL 里的 `user:pass@` 会被抹掉）、压成单行、限长 160 字。
