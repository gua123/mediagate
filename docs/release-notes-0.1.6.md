## mediagate 0.1.6

排查「账号密码都是对的，却报认证失败」时做的加固——**没有改我们的认证代码**（本机对同一台服务器实测 6/6 通过），
而是把"App 里那份密码和你想的不是同一个字符串"这件事变得**不可能发生、发生了也一眼看得出**。

### 新增 / 修复
- **密码框加输入约束**：改用密码键盘（`KeyboardType.Password`）、**关闭自动大写与自动纠错**——
  中文输入法会把 `Qwe980221` 打成全角 `Ｑｗｅ９８０２２１`，而密码框是圆点显示，肉眼根本看不出来。
- **密码框加「显示 / 隐藏」**：点一下就能看到实际字符，全角字符、首尾空格一眼可见。
- **账号框**同样关掉自动大写与纠错（账号也可能是全角）。
- **校验点名**：密码/账号含全角字符、或密码首尾有空格时，输入框下面直接红字提示
  （只提示，**绝不擅自改写密码**——万一对方服务器真接受全角密码呢）。
- **「测试一下」标明用的是哪份密码**：「〔使用：本次新输入的密码〕」/「〔使用：已保存的密码〕」；
  认证失败且用的是已保存的密码时，追加一句自检建议：
  「试试在密码框里重新输入一遍密码再点「测试一下」：如果这次通过，说明存着的那份密码不对（留空=沿用旧密码）。」

### 怎么自查（30 秒）
1. 「连接」页 → 点开那条 SFTP 连接 →「编辑」；
2. 点密码框右边的「显示」，看看字符是不是**半角**、有没有多余空格；
3. **先什么都别改**，直接点「测试一下」——结果会写明"使用：已保存的密码"；
4. 再在密码框里**重新输入一遍**密码，点「测试一下」——这次写明"使用：本次新输入的密码"。
   - 第 4 步通过、第 3 步失败 → 存着的那份是错的，保存即可；
   - 两步都失败 → 输进来的这个字符串服务器不认（多半就是全角/空格/大小写），按红字提示修正。
