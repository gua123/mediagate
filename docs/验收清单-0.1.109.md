## 0. 开工前（3 分钟）

1. **留退路**：先截一张「连接」页列表和首页图，记下当前连接名与地址；再留一份 0.1.83 的安装包，出事能装回去。
2. **装包**：用与旧版**同签名的 release 包**覆盖安装，连接记录与播放进度才会保留。debug 包签名不同，装之前得先卸载，连接、进度会一起清掉。
   构建命令（在仓库根目录）：`source scripts/env.sh` → `./gradlew :app:assembleRelease`（或 `:app:assembleDebug`）。
3. **测试素材**：见附录 A。至少要有 1 个 MP4、1 个 HEVC 的 .ts、1 个文件名带 `#` 的视频；P2 再补大文件与 .m2ts/.m3u8。
4. **统一回传格式**（每项失败都按这个发我）：
   - 条号（如 P0-3）+ 第几步出错；
   - 出错界面**截图**（带时间轴 / 错误文字 / 连接名）；
   - 底部导航「设置」→「诊断与日志」→「展开」→「诊断与崩溃日志」卡 → **「复制全文」**，把全文贴给我（里面有崩溃堆栈、上次退出原因、面包屑、最近播放指标）；
   - 连接类问题再补一张卡片上「测试连通性」的三段耗时截图；
   - 涉及播放的补：协议、文件名、文件大小、编码（H.264 / HEVC）。
   > 截图里把真实域名、内网 IP、账号遮掉；本清单里的 `192.168.1.10` / `dav.example.com` 都是示例值。

## 2. P0 必验（8 项，建议 40 分钟）

### P0-1｜视频真的由 LibVLC 在播（不是悄悄回落 Media3）
- **验什么**：视频内核整体换成 LibVLC 3.7.7；Media3 只在探针失败/构造异常时内部兜底，界面上不该再有第二个内核入口。
- **怎么做**：① 首页 →「媒体入口 · 视频」→ 进目录点一个 MP4，播 10 秒；② 看播放页顶栏，应只有「返回 / 标题 / 更多（滑杆图标）/ 旋转」，**没有**「内核」按钮；③ 退出播放页 → 底部导航「设置」→「诊断与日志」组点「展开」→ 看卡里「最近播放：」。
- **期望**：有画面、进度条在走；没有弹出「LibVLC 内核在本机起不来，已自动改用 Media3 播放」；「最近播放」最新一行以 `LibVLC：` 开头（形如 `12:03:41  LibVLC：LibVLC · 自动（硬解优先）· 网络缓存 1500 ms`，ms 数按 P0-3 的连接类型变）。
- **失败回传**：播放页截图（重点看时间轴是不是 0:00、中间是不是一个播放键）+ 诊断「复制全文」+ 是否出现过那句回落提示 + 连接名。
- **依据**：`docs/plan.md` §4.6；0.1.84 换核说明、0.1.98「只用 LibVLC」、0.1.109 工作区。

### P0-2｜默认硬解，三档解码都能切、都能播
- **验什么**：默认「自动（硬解优先）」，切「强制软解」「强制硬解」后同一视频仍能播（plan R10）。
- **怎么做**：① 准备一个 HEVC 的 .ts（或 4K MP4）；② 播放 → 顶栏「更多」→「播放设置」→「解码模式」应显示「自动（硬解优先）」；③ 点这一行 → 变「强制软解」，画面会短暂黑屏并提示「切换解码模式时画面会短暂黑屏，请稍候」→ 等 5 秒看还有没有画面、位置有没有接上；④ 再点 →「强制硬解」→ 同样看画面；⑤ 再点回「自动（硬解优先）」；⑥ 每换一档，退出重开同一文件，再看「最近播放」。
- **期望**：三档都能出画面、进度基本接上；软解档手机明显更热更费电但不崩；「最近播放」里的档位文字与当前选择一致；不出现只有声音没有画面。
- **失败回传**：卡在哪一档、截图、诊断「复制全文」（含「最近播放」行）、视频编码（H.264 / HEVC）。
- **依据**：`docs/plan.md` §4.6（AUTO_HW / FORCE_SW / FORCE_HW）、§10 R10；0.1.84 硬解说明。

### P0-3｜缓存三档：局域网 1500 / 公网 4000 / 本地 1000
- **验什么**：LibVLC 的时间型缓存随连接地址的网络类型走（不是磁盘缓存）。
- **怎么做**：① 连接页把**局域网**连接「设为当前连接」→ 播同一视频 → 退出 → 设置 →「诊断与日志」→「展开」看最新一行；② 换成**公网**连接「设为当前连接」→ 退出重开视频 → 再看；③ 连接页「本地目录」→「改用本地目录（取消当前连接）」→ 播本地同一文件 → 再看。
- **期望**：三处「最近播放」分别是 `网络缓存 1500 ms`、`网络缓存 4000 ms`、`网络缓存 1000 ms`。体感上公网档起播/切集更慢一点，但播放中更抗抖动；局域网档起播更快。
- **失败回传**：三条「最近播放」截图（注明对应哪条连接）+ 每条连接的地址标签（局域网/公网）。
- **依据**：`docs/plan.md` §4.6 缓存档位；`VlcCachePolicy`（当前工作区含未提交的「未知档 3000→1000」修正，UI 上碰不到未知档）；0.1.84 发布说明。

### P0-4｜一条连接只有一个地址、一种网络类型
- **验什么**：2026-11-01 的连接模型——不再挂「局域网 + 公网」两条地址，也不再先内网后外网自动切。
- **怎么做**：① 连接页右下「+」→ 协议选 WebDAV → 填名称；② 看地址区：**只有一张地址卡**，左边按钮显示当前网络类型（「局域网」或「公网」），点它可在两者间切；③ 切成「公网」→ 填主机/IP（示例 `192.168.1.10`）、传输方案 `http`、端口（WebDAV 默认 80）、根路径（示例 `/media`）→「测试一下」→ 保存；④ 看卡片；⑤ 再点「编辑」看一遍。
- **期望**：编辑器里始终只有一张地址卡，没有「添加地址」「再加一条同一服务器的另一条网络」这类入口；卡片信息行是「WebDAV · **1 个地址** · 状态」，地址行是「公网 · http://…」；再次编辑仍只有这一条。
  > 小提示：连接页「当前网络」卡与地址区标题的旧版多地址文案已在 0.1.109 一并修正（改为「一条连接只有一个地址、一种网络类型」与「地址（一条连接只配一个）」）。若在真机上仍看到「先内网后外网」「局域网 + 公网可各配一个」这类旧文案，说明装的是旧包，请先确认版本号。判据始终是「只有一张地址卡、卡片只列一条地址」。
- **失败回传**：编辑器截图 + 卡片截图 + 连接名 + 是不是从旧版升级上来的（旧库可能残留多条地址）。
- **依据**：`docs/plan.md` §4.5；`AGENTS.md` §2/§5；`eb6d564`、`f5e2d36`、`24cd7b8`。

### P0-5｜「复制连接」是全量复制，并直接打开副本编辑器
- **验什么**：卡片上的复制动作统一为全量复制（协议、地址、根路径、账号、密码、选项），复制完弹编辑器。
- **怎么做**：① 在一条能正常测通的连接上，点地址行右侧的**复制图标**（或卡片右上角菜单按钮里的「复制连接」）；② 看弹出的「编辑连接」；③ 直接「保存」；④ 在列表里对副本点「测试连通性」。
- **期望**：副本名为「原名 副本」；协议/地址/根路径/账号与原连接一致；密码框显示「已保存（留空表示不修改）」；保存后列表出现副本，测试能通过。
  > 复制在点下时就已经落库，点「取消」不会撤销副本（再删掉即可）。
- **失败回传**：副本编辑器截图 + 原卡片截图 + 测试结果截图。
- **依据**：`docs/plan.md` §4.5；`f5e2d36`、`24cd7b8`（0.1.84 区间）。

### P0-6｜换个连接后，不再拿本地目录去读远端路径（404）
- **验什么**：0.1.108 的跨后端恢复保护——播放中切回本地后，通知栏/恢复请求还带着远端路径时，新逻辑会忽略它，而不是报「文件不存在」。
- **怎么做**：① 用**远端连接**播一个视频，让它出声出画；② 返回 →「连接」页本地目录卡点「改用本地目录（取消当前连接）」；③ 下拉通知栏，点视频播放通知回 App（通知没了就从最近任务点回）。
- **期望**：不出现「播放失败 / 文件不存在」这类错误面板，也不出现 0:00 黑屏；App 停在浏览页或当前页，不会用本地目录去读远端路径。
- **失败回传**：错误面板截图（含错误原文）+ 操作时间点 + 诊断「复制全文」（关键词：`忽略跨后端恢复`、`恢复超时`）。
- **依据**：0.1.108 发布说明；`MainActivity.acceptedDebugOpen`。

### P0-7｜连续切集不再撞 MediaSession（`Session ID must be unique`）
- **验什么**：0.1.109 给视频/音频会话加了唯一 ID，旧会话没释放也不会撞车。
- **怎么做**：① 先去「音乐」播一首、让它出声，返回；② 打开一个本地或局域网视频，底栏「下一集」连点 10 次以上（也可「更多」→「列表」→ 同文件夹，点 5 个不同文件）；③ 回「音乐」再播一首，再回视频切 3 次。
- **期望**：每一集都能起播；不出现「播放失败」面板、不出现 0:00 黑屏；不出现 `Session ID must be unique`；视频与音乐切换时声音不叠在一起（后开的那个接管音频焦点）。
- **失败回传**：第几集开始出错 + 错误面板截图 + 诊断「复制全文」；有 adb 的话补 `adb logcat -d` 里含 `Session ID must be unique` 的几行。
- **依据**：0.1.109 发布说明；`VideoPlaybackService` 唯一 ID 注释。

### P0-8｜冷启动/后台被回收后恢复播放，不 404
- **验什么**：0.1.109 的「带 backendId 的恢复请求先等目标后端最多 10 秒，等不到就放弃」。
- **怎么做**：① 公网连接播一个视频 → 按 Home → 从最近任务把 App 划掉（通知跟着消失就跳过点通知这步）；② 重新点桌面图标进 App；③ 若通知还在，点通知。
- **期望**：进 App 不弹「播放失败 / 文件不存在」；若出现播放页，应在 10 秒左右开始出画面（等后端的上限是 10 秒，起播时间另算）；等不到就安静停在浏览页，不把错误甩到脸上。
- **失败回传**：从点图标到出画面的秒数 + 截图 + 诊断「复制全文」（关键词：`等待播放后端就绪`、`恢复超时，已放弃`）。
- **依据**：0.1.109 发布说明；`MainActivity.restoreDebugOpen`（`withTimeoutOrNull(10_000L)`）。

## 3. P1 回归（8 项，建议 30 分钟）

### P1-1｜本地源：能播、能拖
- **怎么做**：首页「存储位置」确认是本地目录（远端在用就先按 P0-3 第③步切回本地）→「媒体入口 · 视频」→ 点一个 MP4 → 播 10 秒 → 拖进度条到 50% 松手 → 再拖回 25%。
- **期望**：起播正常；松手后 ≤3 秒出画面（本地只会更快）；画面与声音对得上。
- **失败回传**：文件名/大小 + 拖拽耗时 + 截图 + 诊断「最近播放」。
- **依据**：plan §10 R1/R4。

### P1-2｜WebDAV：能列、能播、能拖
- **怎么做**：连接页新建 WebDAV（示例 `http://192.168.1.10:8080`，根路径 `/media`）→ 若提示「已禁止明文 http」，把「允许明文 http」打开 →「测试一下」→ 保存 →「设为当前连接」→ 首页「视频」→ 进目录播 MP4 → 拖到 50%。
- **期望**：目录能列出来；播放出画面；局域网松手到出画面 ≤3 秒、公网 ≤6 秒；连续拖 20 次不错位。
- **失败回传**：「测试连通性」三段耗时截图 + 播放页截图 + 诊断全文。
- **依据**：plan §10 R2/R4；0.1.97（代理响应头 flush）。

### P1-3｜SFTP：能播，文件名带 `#` 也不 404
- **怎么做**：新建 SFTP（示例 `sftp://192.168.1.10:22`，填账号密码）→「测试一下」→ 保存 →「设为当前连接」→ 进目录找一个**中文或带 `#` 的视频**（例：`#测试#片段.mp4`）→ 播放 → 拖到 50%。
- **期望**：目录能列、能播、能拖；带 `#` / `?` / `%` 的文件名不报 404（0.1.88 改成 base64url token 走代理）。
- **失败回传**：出错文件名原文 + 截图 + 诊断全文（关键词 `404`、`文件不存在`）。
- **依据**：plan §10 R2；0.1.88 发布说明。

### P1-4｜FTP：能列、能播、能拖
- **怎么做**：新建 FTP（示例 `ftp://192.168.1.10:21`，填账号密码）→「测试一下」→ 保存 →「设为当前连接」→ 播一个 MP4 → 拖到 50%。
- **期望**：目录能列；播放出画面；拖拽 ≤3 秒（局域网）/≤6 秒（公网）。
- **失败回传**：测试结果截图 + 播放页截图 + 诊断全文。
- **依据**：plan §10 R2/R4。

### P1-5｜拖拽 seek 专项：20 次不错位
- **怎么做**：用局域网连接打开一个 ≥500 MB 的 MP4；在 25% / 50% / 75% 之间轮流拖 20 次，每次都等画面出来再拖下一次；再对一个 .ts 拖 3 次。
- **期望**：每次松手 ≤3 秒出画面（公网 ≤6 秒；有 TS 索引时 ≤1.5 秒）；20 次不错位、不黑屏、不永久「正在缓冲…」。
- **失败回传**：第几次失败、当时的百分比、截图 + 诊断「最近播放」行。
- **依据**：plan §10 R4；0.1.97 发布说明。

### P1-6｜音频后台播放：锁屏与通知栏都能控
- **怎么做**：首页「音乐」→ 播一首 → 返回 → 按 Home → 锁屏 → 用锁屏卡片暂停/继续 → 解锁下拉通知栏，再用通知栏播放/暂停。
- **期望**：通知栏有媒体控制（标题 + 播放/暂停）；锁屏可控；连续放 ≥30 分钟不断；被别的 App 抢音频焦点时暂停、焦点回来自动续播。
- **失败回传**：通知栏/锁屏截图 + 断了的时间点 + 诊断全文。
- **依据**：plan §10 R18、§4.11；0.1.84 音频焦点说明。

### P1-7｜视频息屏后台音轨 + 回前台画面恢复
- **怎么做**：播一个视频 → 按电源键息屏 30 秒（听到声音继续）→ 解锁回 App；再试一次：按 Home（会进画中画）→ 从通知栏点回播放页。
- **期望**：息屏期间声音继续；回前台/点通知能回到播放页，画面恢复，不出现「有声音、画面黑」。
- **失败回传**：回前台截图 + 诊断「复制全文」（关键词：`后台回前台`、`recoverVideoOutput`）。
- **依据**：plan §10 R18；0.1.104 发布说明。

### P1-8｜退出播放页恢复竖屏（0.1.103）
- **怎么做**：播放页顶栏点「横屏」→ 等画面转过去 → 按返回退出播放页。
- **期望**：回到浏览页是竖屏；再进另一个视频，起始也是竖屏（除你再次点横屏）。
- **失败回传**：退出后的截图 + 是否还能手动转回竖屏 + 诊断全文。
- **依据**：0.1.103 发布说明。

## 4. P2 边界（6 项，建议 30 分钟）

### P2-1｜大文件：2 GB 级也能拖
- **怎么做**：放一个 2 GB 级的 .ts（至少 ≥1 GB；或 2 GB MP4）到本地或局域网 → 播放 → 拖到 80% → 继续播 1 分钟。
- **期望**：音画同步；局域网拖拽 ≤3 秒出画面；不崩、不被系统杀。
- **失败回传**：文件大小/时长 + 截图 + 诊断全文。
- **依据**：plan §10 R3/R4。

### P2-2｜非常见扩展名与 .m3u8
- **怎么做**：准备 `.m2ts` / `.mts` / `.tp` 各一个（把同一个 .ts 复制改扩展名即可）和一个 `.m3u8`（带分片）→ 浏览页顶栏「筛选类型」选「视频」→ 逐个播放。
- **期望**：都被识别成视频并能起播；m3u8 正常起播；无 PCR 的拼接 TS 底部有提示、点「修复时间戳」后能正常拖。
- **失败回传**：哪个扩展名失败 + 截图 + 诊断全文。
- **依据**：plan §4.3、§10 R3。

### P2-3｜断网重连：飞行模式 10 秒再回来
- **怎么做**：公网连接进到某个目录 → 开飞行模式 10 秒 → 关掉 → 回 App，点「返回上级」再进该目录（或直接点「重试」）。
- **期望**：目录能恢复，不用重启 App；不出现永久「正在加载…」或连接卡死。
- **失败回传**：截图 + 连接测试结果 + 诊断全文（关键词：`自愈`、`closeRemoteRoot`）。
- **依据**：0.1.93（回前台自动重建）、0.1.101（目录自愈）。

### P2-4｜换网络类型：Wi-Fi ↔ 5G
- **怎么做**：① 公网连接在 Wi-Fi 下播一个视频 → 关 Wi-Fi 用 5G → 重开同一视频；② 把**局域网**连接设为当前，在 5G 下点「测试连通性」。
- **期望**：① 公网连接在 5G 下仍能播，诊断行显示 `网络缓存 4000 ms`（不因换网复用旧的局域网判断）；② 局域网连接在 5G 下给出明确中文错误（超时/不可达），不会假装成功。
- **失败回传**：两种情况的测试结果截图 + 诊断「最近播放」+ 当前网络（Wi-Fi/5G）。
- **依据**：`a846e39`（5G 不再复用旧局域网地址）+ 单地址模型（`docs/plan.md` §4.5）。

### P2-5｜公网冷启动：等 12 秒，目录自己回来
- **怎么做**：把公网连接设为当前 → 杀进程（最近任务划掉）→ 重开 App → 进「视频」或「浏览」看目录出不出来。
- **期望**：12 秒内自动连上并列出目录，不用手动去连接页点重连；若仍空，点「重试」能恢复。
- **失败回传**：等了多久 + 截图 + 诊断全文（关键词：`冷启动补连`、`applyCurrentConnection`）。
- **依据**：0.1.101 发布说明。

### P2-6｜SFTP 从子目录「返回上级」不卡加载
- **怎么做**：公网 SFTP 进到二层子目录（例 `/a/b`）→ 连点「返回上级」两次。
- **期望**：每次都立刻列出上级目录，不出现一直「正在加载…」或空目录。
- **失败回传**：截图 + 诊断全文。
- **依据**：0.1.102 发布说明。
