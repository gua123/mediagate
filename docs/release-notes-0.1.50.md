## mediagate 0.1.50 —— 回答「你如何判断局域网和公网是同一个链接」，并顺手把护栏加厚

### 直接回答：**我不判断，判断权在你的数据模型里**

缓存命名空间用的是**连接记录的主键**（`"conn:" + 连接id`），不是什么地址推断：

- 你在「编辑连接」里给**同一个连接**加了两条地址（局域网 `192.168.x.x:5005` + 公网 `vpn.gua233.top:20005`）
  ⇒ 它们**天然**共享同一份缓存；
- 两个**不同连接**（各自的记录）⇒ 一律各存各的，绝不串味（有单测）。

也就是说：**"这两条地址是同一台服务器"这件事，由你放在同一个连接里来表达**，
App 不去猜（IP 会因为宽带重播而变、域名可能走 CDN/反代，猜不可靠）。

### 那如果同一个连接里的两个地址其实是两台不同服务器？

那是"数据模型与事实不符"，App 无法知道你心里的意图——所以这一版把护栏加厚了：

| 护栏 | 说明 |
| --- | --- |
| **文件指纹**（本版新增） | 打开文件时比对 大小 + 修改时间 + ETag，任一实质不同就**丢掉该文件的旧缓存**重下 |
| 未知字段不参与判定 | 协议不给 mtime/ETag 时（值为 0 / null）不比它，避免"比不了就当成变了"而反复重下 |
| 老格式兼容 | 旧版边车里只写了大小 ⇒ 退化成"只比大小"，不会误清 |

⇒ 两台不同服务器上都是 `/video/a.mp4` 时：**只要大小/时间/ETag 有任何一项不同，就不会拿错字节**；
三项全同才会命中旧缓存（那种情况下两份文件实际上也是同一份内容）。

### 另外可选（你要就说）

如果你希望**更严格**：可以在连接里加一个显式开关「这些地址是同一台服务器（共享缓存）」——
默认按"同一个连接＝同一台服务器"，关掉就完全按地址各存各的。
