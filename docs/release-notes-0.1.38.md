## mediagate 0.1.38

### 你截图里的对话框，我看懂了两件事

1. **对话框本身工作正常** ✓ 三个按钮都在：「仍然切换 / 先不切 / **先测试再切换**」（0.1.29 加的入口）；
2. **探针跑了，但给出的是"没得到结论"** ✗ —— 也就是那句
   「这次没得到结论（探针进程可能被系统回收了），可以稍后再试」。

### 为什么会"没得到结论"（我的判据写得太依赖系统 API）

原来的判据是：探针写了 `start`、没写 `ok` 时，去问系统「探针进程上次是怎么退出的」（`ApplicationExitInfo`）——
只有系统说是"崩溃类"才判不可用。真机上**这个反射调用拿不到东西**，于是结论永远是"未知"。
等于你按了按钮，它还是没告诉你该不该切。

### 这一版换成了"看探针自己的脚印"（不依赖任何系统 API）

探针现在留三个文件：

| 文件 | 含义 |
| --- | --- |
| `start` | 开始测了 |
| `ok` | LibVLC 初始化**返回了**（可用） |
| **`done`** | 这段代码**执行到底**（无论成功还是抛了 Java 异常）——本轮新增 |

判据：`start` 有、`ok` 没有、`done` 也没有 ⇒ **进程在初始化中途被带走了** ⇒ 判「**本机跑不了 LibVLC**」。
（误判的代价可控：界面永远留着「重新测试」，下次会重跑。）

### 请你再按一次

装 0.1.38 → 播放页点「内核」→ 点「**先测试再切换**」。预期这次它会给一个**明确的结论**：

- 要么「**测试通过：本机可以运行 LibVLC 内核**」并直接切过去；
- 要么「**测试失败：LibVLC 内核在本机起不来（已阻止切换）**」——那就说明这台机器确实用不了 LibVLC，
  以后这个按钮不再劝你冒险，软解请用「解码 → 强制软解」。
