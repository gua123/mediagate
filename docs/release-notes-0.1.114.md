# 0.1.114

## 修好了：进大目录就闪退

- **症状**：一个目录里几百个视频，刚点进去几秒就闪退，或者滚着滚着突然退回桌面。
- **原因**：后台同时干活的线程没有上限——每一行视频都要去远端取缩略图，几百个一起上，线程越开越多，系统撑不住，进程被直接干掉。跟"点哪个文件"无关，跟"目录里有多少文件"有关。
- **现在**：后台线程有明确上限，多出来的活儿排队等，不再无限开。这是这一版最要紧的修复。

## 修好了：从播放页返回后点「首页」没反应

- **症状**：看视频时按返回回到浏览页，再点底部「首页」，界面纹丝不动；有的要从播放页直接退回首页也一样，点了像没点上。切来切去几次之后更明显。
- **原因**：底部页签切换时，首页（App 打开后的第一个页面）也被当成"可以记住上次状态"的页签去恢复。而首页本来就在最底下，没有"上次"可言——它被要求恢复的是**刚才压在它上面的那一页**（浏览页）。于是点「首页」，系统把浏览页又还原了回来，首页被顶掉，看起来就是没反应；每点一次就再存一次、再还原一次，这个圈一直转，只有杀掉 App 重开才恢复。
- **现在**：首页不再参与"记住上次状态"（只有连接、设置这类页签会保留），点「首页」一定回到首页。顺带把"返回浏览页"的判断改成纯函数决策：当前已经停在浏览页时就什么都不做（以前会再叠一层浏览页，正是让上面那个圈更容易出现的帮凶），从播放页/首页点进来该弹几层也算得明明白白。

## 真机验证

- 同一个大目录（几百个视频），进去后连续滚动 60 秒，进程一直在，一次没崩。
- 修之前同样的操作：3 次进去 3 次崩，最快进去 4 秒就没了。
- 播放 → 返回浏览页 → 点「首页」能正常切回；首页、浏览、连接、设置之间反复切换不再卡住，从「最近播放」进播放页再返回也正常。

## 顺带改的

- **缩略图**：滚动时优先出当前看得见的那几张，滚过去看不见的直接丢掉，不再排一长队拖着，列表更跟手。
- **日志降噪**：存储层的超时日志改成抽样打印（每 32 条出 1 条），不再一秒钟刷几百行；真出问题时反而看得清。
- **「预读段数」设 0 现在真的关了**：以前设成 0，SFTP 上仍然按 20 段预读（等于照样往死里读远端），现在设 0 就是不再预读。

## 一句提示

如果你之前遇到过"播放某个视频就闪退"，先别怪那个文件：实测 2.8 GB 的 mkv 播放完全正常。真实原因是**点进它所在的那个目录**时就已经崩了，文件本身没问题。
