## mediagate 0.1.21

你发来的面包屑直接把范围锁死了：

```
07:47:51.862 开始播放：…#Akari 2024.11.9.mp4（内核 Media3）
07:48:01.437 切换内核：→ LibVLC（已释放旧内核）
07:48:03.320 应用启动（versionName 0.1.19）   ← 进程没了，你重开了
```

**打了"切换内核 → LibVLC"，却始终没等到"新内核已创建"**，紧接着就是一次新的启动——说明进程死在
`createEngine(VLC)` 里面，而且没有任何 Java 异常（所以崩溃处理器抓不到）。这是**原生层**的特征。

### 这一版做三件事
1. **把那段再拆细**：面包屑新增「VLC：起回环代理 / 代理就绪 / 建 LibVLC 实例 / 实例建好了」——
   下次再崩，就能分辨是回环代理、LibVLC 实例化，还是画面视图；
2. **不再让你闷头再踩**：判据（纯函数 + 单测）从面包屑识别"上次切 LibVLC 把进程带走了"；
   以后点内核要切 LibVLC 时，先弹一句说明并让你选「仍然切换 / 先不切」——
   想换解码方式也可以直接用「解码」档位，不必走 LibVLC；
3. **等你的那份报告**：崩溃后重开 App，设置 → 诊断与崩溃日志里应该有 `exit-…` 报告（0.1.19 起放宽了退出口径），
   **里面的「系统记录的堆栈/轨迹」会指出是哪个 .so / 哪个函数**——有它我就能判断是 LibVLC 本身与本机不兼容，
   还是我们的调用方式（例如用 application context 建 SurfaceView）有问题。

### 说明
- 包名不变，可直接覆盖安装（含 0.1.20 横屏紧凑化）。
