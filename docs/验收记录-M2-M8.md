## 5. 已知限制（不阻塞交付，记录在案）

- **R4 索引尚未接进播放器**：`tsext` 的 `seekTarget` 已就绪但播放页未使用，大 TS 拖拽目前仍靠 DataSource 的 Range，达不到"毫秒级"目标。
- **Media3 无强制硬解开关**：`FORCE_SW` 只能靠 softwareOnly 解码器过滤，无软解器时如实回退并在 `DecoderReport.note` 上报；真软件解码走 LibVLC。
- **Media3 1.11 无字幕延迟 API**：外挂字幕改用 Compose 覆盖层渲染（同时满足样式可调 + ±0.5 s），引擎侧字幕轨道保留给内嵌轨。
- **ASS 仅基础样式**：Alignment/字体/字号/主色/粗斜体；不支持 `\pos` 精确定位、`\k`、特效。
- **whisper 模型 sha256 为空**：官方未发布校验和，当前只校验精确字节数，首次真机下载后回填即可启用强校验。
- **视频会话生命周期**：会话只在播放页持有内核期间存在，退出播放页即收掉（R18 覆盖切后台/息屏，不含退出播放页）。
- **连接页缺 SAF 选择器入口**（选目录仍走首页）；首页「当前根目录」卡片在远端连接下文案未统一。
- **主机密钥指纹未持久化**（仅内存 TOFU）；分段缓存（降级链第二级）未实现。
- **通知栏/锁屏封面未接**（只有标题与文件名）；音频封面无同目录 `cover.jpg` 兜底。

## 7. 真机验收反馈与修复（2026-10-02，提交 `1a3b693`）

**现象**：真机上建好 SFTP 连接后，界面到处写着「（M5 接入）」「后端将在 M5 接入：现在只能测试连通性」；
即使点「设为当前连接」，浏览的仍是本地根目录。

**根因**：M5 交付的是**数据层后端**（`data/storage-sftp` / `data/storage-ftp`，含真网验收），
**App 组合根那一段没接**——M4 写死的两分支一直留到 M8：

| 漏接点 | 真机症状 |
| --- | --- |
| `AppContainer.applyCurrentConnection` | 只有 WEBDAV / LOCAL 两个分支，SFTP / FTP 落到 `else` 只打日志、继续用本地根目录 |
| `ConnectionRecord.browsable` | 只放行 LOCAL / WEBDAV，SFTP / FTP 被判「不可浏览」 |
| 协议选择器 `connections_protocol_pending` | 下拉里写着「SFTP（M5 接入）」 |
| 设置页 `settings_note_protocol_detail` | 写着「SFTP / FTP 计划在 M5 接入」 |
| `core:network` 的 `NOT_IMPLEMENTED` 文案 | 提示「协议握手待 M5」 |

**修复内容**：
1. 新增 `ConnectionBackends`（:feature:connections）：连接记录 + 首选地址 → SFTP / FTP 后端配置的**纯函数装配**
   （端口、根路径、连接超时、`connection.tls` → FTPS 模式、后端重建指纹），与连通性测试共用同一套字段口径；
2. `AppContainer`：WebDAV / SFTP / FTP 走同一条「选路 → Keystore 解密 → 建后端 → 发布根目录」流程
   （`selectAddress` / `installRemoteRoot`）；SFTP 主机密钥用进程内共享的 TOFU 校验器（指纹变更照旧告警并拒绝连接）；
3. **切不过去时如实告知**：缺用户名 / 缺密码 / 配置不合法 / 当前网络没有可用地址，都用中文 Snackbar 说明
   （原来是静默留在本地根目录，用户只看到"点了没反应"）；
4. `browsable` 改为「四协议都可以，只有数据库里认不出的协议标识才为 false」，并清掉全部 M5 陈旧文案。

**证据（本工作区实测）**：
- 新增 `ConnectionBackendsTest` 8 例；`ConnectionsUiStateTest` 改为「四协议都能浏览，只有认不出的协议标识才是 false」；
- 受影响模块：core:network 70 / feature:connections 69（+8）/ feature:settings 16 / app 8，全部 0 失败；
- 全项目 `./gradlew testDebugUnitTest --rerun-tasks --no-build-cache`：**1272 例 0 失败**（M2–M8 基线 1264 + 新增 8）；
- `:app:assembleDebug` 与 `:app:assembleRelease` 均通过，release 包已更新到 `dist/mediagate-0.1.0-正式版.apk`。

**仍未做（继续留在第 5 节「已知限制」）**：SFTP 主机密钥指纹只存在内存里（冷启动重新 TOFU，未落库），

## 8. 真机验收反馈与修复（二）：明文 http 被系统策略拦死（2026-10-02，提交 `0af4e6a`）

**根因**：清单里既没有 `android:usesCleartextTraffic` 也没有 `android:networkSecurityConfig`。
Android 9（API 28）起 **targetSdk ≥ 28 的应用默认禁止明文流量**，本应用 targetSdk 36 →
真机上 OkHttp / HttpURLConnection 对任何 `http://` 地址都会直接抛
`CLEARTEXT communication to ... not permitted by network security policy`。
而局域网那台 WebDAV 正是 `http://192.168.1.10:8080`（第 0 章的实测结论），**等于 WebDAV 在真机上全挂**。
1264 个 JVM 用例跑在 JVM 上、不受系统网络策略约束，所以一个都抓不到——与第 7 节 SFTP 接线同类的
"真机才暴露"缺口（已并入 M9 修复）。

**修复内容**：
1. 新增 `app/src/main/res/xml/network_security_config.xml`：`base-config cleartextTrafficPermitted="true"`
   ＋信任系统根证书；「要不要走明文」仍由两层把关——连接页的 per-连接开关 `allowInsecureHttp`，
   以及 `WebDavConfig` 在 scheme=http 且开关关闭时直接拒绝构造；
2. 清单挂上 `android:networkSecurityConfig`；
3. 新增 `CleartextPolicyTest`（:app，2 例）做回归护栏：清单必须挂配置、配置必须放开明文——
   这条以后被子代理改回去会立刻红。

**证据**：app 模块 10 例（+2）0 失败；全项目 `testDebugUnitTest --rerun-tasks --no-build-cache`
**1274 例 0 失败**（第 7 节修复后的 1272 + 本节 2 例）；`:app:assembleDebug` / `:app:assembleRelease` 通过；
aapt2 在 release 包内可见 `xml/network_security_config`（资源压缩后为 `res/8G.xml`，引用仍在清单里）；
dist/ 交付包更新为 74,186,126 B，SHA-256 `1ff62c85…39285c`，V2 签名不变。

## 9. 界面语言：错误提示统一中文（2026-10-02，提交 `e021c6c`）

**用户要求**（原话）：「同时 app 中界面的语言直接使用中文即可，不需要中英双语」。

**排查结论**：字符串资源本来就是纯中文——17 条「中英混排」全是 WebDAV / SFTP / FTP / Wi-Fi / TCP /
SSID / LibVLC / VTT 这类专有名词，没有任何一条是中英对照或英文句子；各模块也没有 `values-en` 之类的语言目录。
**真正会露出英文的是底层库异常的 message 被直接拼进提示**，最典型的是明文被拦那次会显示
`网络不可达：UnknownServiceException CLEARTEXT communication to 192.168.1.10 not permitted by network security policy`。

**修复内容**：
1. 新增 `:core:common` 的 `ErrorText`（**R16**）：含汉字的消息原样保留 → 按异常类型归类
   （UnknownHost / SocketTimeout / Connect / NoRouteToHost / SSL）→ 英文关键词归类（明文被拦 / 超时 /
   拒绝 / 不可达 / 证书 / 连接被中断 / 认证 / 路径 / 只读）→ 兜底「操作失败（详情见诊断日志）」；
   原始异常仍由 `AppLog` 记录，诊断能力不降级；
2. 接入点：连接页一次性提示、:app 的远端连接提示、WebDAV probe 失败、SFTP 的 `describeThrowable` /
   网络错误 / 连接失败、FTP probe 兜底、LibVLC 装载失败、批量字幕列目录、TS 扫描失败、
   whisper 引擎不可用、SFTP 主机密钥校验器自身异常；
3. 时间戳重建失败不再把 ffmpeg 的英文 stderr 贴进提示（仍在 `result.output` 里可查）；
4. 新增 `ErrorTextTest` 5 例锁定口径（自己的中文原样保留 / 明文给可照做的中文 / 常见英文归类 / 认不出与空消息走兜底 / 汉字判定）。

**未改的**：应用名仍是 `MediaGate`（launcher 标签），符合"项目标识用英文"的既定约定；
协议名（WebDAV / SFTP / FTP）、格式名（SRT / VTT / ASS）、编解码名按专有名词保留。

**证据**：全项目 **1279 个 JVM 用例 0 失败**（上一节 1274 + 本节 5 例）；
