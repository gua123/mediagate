# 0.1.82 发布说明

> 0.1.82 按你拍板的方案做缓存改造：**访问 LRU + 自适应预读 + 统计**；
> 硬解保持默认、不做按编码器开关；渲染器不做。另附一份同路径 SFTP 视频的段大小基准。

## 缓存

- **命中缓存会刷新 LRU**：以前只看段文件的"下载时间"，导致刚看过的热段和很久没看的冷段一样旧，
  缓存紧张时热段可能被误淘汰。现在命中即更新访问顺序（内存序号，不额外写盘）。
- **自适应预读**：按最近一次下载吞吐与"刚 seek 过"状态，把一次滑窗抓取从固定的 4 段往下收：
  弱网/刚拖动时只抓 1–2 段，稳定高速才用满你设置的上限；**预读永远给播放让路**。
- **缓存统计进诊断卡**：命中/请求、下载字节、最近吞吐、段大小与预读段数；
  真机截图就能判断"是缓存命中低，还是网络慢"。
- **段大小基准**：用同一个 SFTP 视频（约 1 GB）测 1/2/4/8 MB 段，4 MB 综合最好，
  **默认保持 4 MB**；明细见 docs/验收记录-网络加载-SFTP基准.md。

## 硬解

- 按你的要求：**不做按编码器硬解开关**，保持默认硬解优先；
- 诊断卡新增 **常见编码覆盖**：H.264 / HEVC / VP9 / AV1 / MPEG-4 / MPEG-2 / H.263 各自
  有多少硬解/软解；设备缺硬解时会如实显示（不静默）。
- 顺手去掉了解码提示里"切 LibVLC"这类过期文案。

## 明确没做

- 渲染器 SurfaceView/TextureView 切换（你拍板不做）；
- 按编码器软/硬面板（你拍板不做）；
- 缓冲 1/2/15 秒档位、nPlayer 式 64 KiB 块表（B 方案）、SMB/NFS——留到后续。

## 验证

- 新增：LRU 热/冷段回归、冷读/命中统计、自适应预读策略、滑窗 0/1/2 段；
- SFTP 基准：`MEDIAGATE_BENCHMARK=1` 才会跑，平时跳过；
- 全量 **1381 用例通过、1 个基准用例按设计跳过（0 失败）**；release 包 0.1.82 / versionCode 83。
