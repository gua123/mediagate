## mediagate 0.1.22

按你的建议做的：**启动时先测内核；跑不了的内核，直接不让切，并且测试本身绝不会把 App 弄崩**。

### 怎么做到"测试不会崩 App"
关键点：**测试跑在独立进程里**（`android:process=":vlcprobe"`）。
LibVLC 的坑是它在初始化时可能**直接把进程带走**（原生崩溃，Java 抓不住）——放在独立进程里，
崩的只是那个探针进程，主 App 毫发无损。

### 判定方式（三段证据）
探针进程会留下两个小文件：`start`（开始测，先写）与 `ok`（LibVLC 与 MediaPlayer 都建起来了）。
主进程在探测结束后看三样东西——开始过吗？写下 ok 吗？系统记录的**探针进程**退出原因是什么？
· 有 ok → **可用**；
· 开始了但没有 ok、并且系统记为**崩溃类**（原生崩溃/被信号杀/ANR）→ **本机不可用**；
· 只是被系统按低内存回收 → 判**未知**（不算不可用，下次再测）。
这套判据是纯函数，**+5 个单测**穷举（含"低内存被回收不能误判"这一条）。

### 界面上的变化
- 本机不可用时，点内核**不再切**给 LibVLC，而是弹一句：
  「**本机不能用 LibVLC 内核**」+ 原因说明 + 「**重新测试**」按钮；
  想换解码方式仍然可以用底部「**解码**」档位（自动/强制软解/强制硬解）；
- 上次切 LibVLC 崩过、但探针还没给结论时，仍是原来的「仍然切换 / 先不切」提示；
- 探针结果会落盘，重启后仍记得（判"未知"时不会把已有结论冲掉）。

### 说明
- 包名不变，可直接覆盖安装（含 0.1.21 的细粒度面包屑）。
