## mediagate 0.1.39

### 你那段「技术详情」把公网那条结案了：**不是 App 的问题**

```
[1] http://vpn.gua233.top:20005
    结果：失败
    卡在：协议握手（HANDSHAKE）
    分类：服务器内部错误（SERVER_ERROR）
    原始信息：HTTP 503 Service Unavailable（请求：http://vpn.gua233.top:20005/）
    耗时：DNS 210 ms · TCP 2 ms · 握手 593 ms（合计 805 ms）
```

我在开发机上把同一个地址**跑了两遍**，结论非常干净：

| 走法 | 结果 |
| --- | --- |
| **直连**（不走代理） | **HTTP 207**，`Server: Apache` ✅ |
| **经系统代理** | **HTTP 503**，`Proxy-Connection: close` ❌ |

你手机上拿到的正是 **503** ⇒ **请求在链路中间被代理/VPN 挡下来了**，服务端和 App 都没问题
（你看状态栏那个 VPN 图标；另外小米的 Wi-Fi 设置里也能单独配 HTTP 代理）。

### 所以这一版加了"把这条线索写进提示"

以后探针失败时，如果系统/网络里配了 HTTP 代理，提示里会多一句 **（经系统代理 10.0.0.1:8080）**——
一眼就能想到"是不是手机开着 VPN / 设了 Wi-Fi 代理"。
（OkHttp 默认就会用系统代理，App 没法替你决定绕过它；但至少现在它会**说出来**。）

### 你可以这样试

1. **把手机的 VPN / 代理关掉**（或在这个 App 上放行），再点一次「测试一下」——
   开发机直连是 207，所以关掉中间那一层大概率就通了；
2. 如果 503 是你自己反代（nginx/群晖）发出来的，那就是后端的 upstream 掉了，看服务端日志；
3. 局域网那条 `192.168.40.6:5005` 你已经验过是**通过**的 ✅，日常在家用它就行。
