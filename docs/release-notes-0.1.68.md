# 0.1.68 发布说明（草稿 · **尚未发布**）

> 这份是 0.1.64 之后攒下的改动草稿。按发版纪律：**能感觉到的改动**才发版。
> 0.1.67 能感觉到的：**播放页内核按钮里多了「自研引擎」**、**设置页重排了**、**诊断卡能看到起播耗时**。

## 修：点了「自研引擎」切不过去（真机 0.1.66 实测）

真机现象：点内核轮到「自研引擎」，画面立刻退回 Media3，面包屑写着
`切换内核失败：自研引擎 → Failed to resolve SessionToken for ComponentInfo{…VideoPlaybackService}`。

两条根因，都修了：

1. **清单少了会话 action**：视频后台播放服务（`VideoPlaybackService`）在清单里没声明
   `androidx.media3.session.MediaSessionService`——Media3 的 `SessionToken` 靠这个 action 反查服务**类型**，
   查不到就抛异常。音频那个服务一直有，视频这个从 M8-A 起就没有（所以视频通知栏/锁屏控制其实一直没连上）。
2. **附属失败被当成内核失败**：换内核那条路没兜住这个异常 ⇒ 自研引擎被判成「播不了」⇒ 自动回退 Media3。
   现在兜底收在 `bindSession` 一处（起播/换集/换内核全部覆盖）：**会话连不上只记日志与面包屑，绝不影响播放**。

顺带加的护栏（都实证过「破坏就能红」）：清单与源码的交叉检查（凡是 `SessionToken` 按组件连的服务，
清单里必须有会话 action）、以及一条单测钉住「会话绑不上也要换内核成功」。
还修了一个**护栏假绿**：Gradle 原来判定测试「最新」会直接跳过（清单不是测试输入），现在清单与 res 已声明成输入。

## 新：缓存明细（能看到哪些文件缓存过了）

你问的「能不能加个界面告诉我哪些缓存过、哪些没有」——**设置 →「网络与缓存」→「查看缓存明细」**：

- 一行一个已缓存的文件：**文件名** + 「已缓存 8.0 MB · 2 段 · 占该文件 8%」+ 完整路径（小字，便于对上号）；
- 头部合计：「已缓存 3 个文件 · 合计 42.5 MB」+ 当前缓存上限；
- 每条右边有**删除**（只清这个文件的段）；顶部有**清空全部**；
- 老版本留下的缓存（那时还没记录文件名）会显示成「旧版本缓存，名称未知」，但一样能删。

说明两点：**没在列表里的文件就是还没缓存过**（远端文件打开过才会按段落到本地）；总大小拿不到时不显示百分比（宁可空着也不瞎算）。

## 修：通知栏一直没有它（视频后台播放的媒体通知）

反馈原话：「**现在点开有封面的视频快了很多，这很好，但是通知栏还是没有**」。

- **根因**：点视频时**从来没申请过通知权限**（音频那条路一直在申请，视频漏了）——
  而 Android 13 以后没有这个权限，系统**什么通知都不显示**，媒体通知也一样；
- 现在点视频会和点音频一样先申请一次；
- 顺带把这条链路的**自述**放进设置页诊断卡：「视频会话：控制器 已连接 · 会话源 有（片名）· 通知权限 已授予」——
  通知栏不出现有三条互相独立的链路（权限 / 会话控制器 / 会话源），这一行能直接指出是哪一条断了。

## 改：上 G 的视频，第一次点开不用等那么久了

按你的反馈：「**针对上 G 大小的视频文件进行特殊缓存优化，现在文件第一次点还是会等待时间比较久**」。

- **点一下就开抓**：以前要等播放页起来才开始预取（那时播放器已经在要数据了），现在**手指点下文件的那一刻**就发出去——
  从"点下"到"播放器发第一条请求"之间还有几百毫秒，这点时间正好省掉一个网络往返（你那条链路一次往返 ≈0.6 秒）；
- **大文件多抓一点**：超过 1 GB 的文件，开头一次抓 3 段（大文件的索引和第一个关键帧常常不在第一段里），
  外加最后一段（MP4 的 moov、MKV 的 cues 一般都在文件末尾）和你的续播位置；
- **不影响播放**：预取永远给播放让路，同一段不会重复下载；文件大小拿不到时**什么都不做**（不瞎猜位置）。

## 改：播放内核回到原来那一个（自研引擎与 LibVLC 下线）

按你的要求：「**画面全没有，所以我想切回原先的引擎，将自研引擎和 libvlc 都去掉吧，原有引擎就可以。**」

- 播放页**不再有右上角那个「内核」按钮**（只剩一个内核，没什么可切的）；
- 旧版本里存过的内核偏好（LibVLC / 自研引擎）会**自动回到 Media3**，不会因此打不开；
- 三种解码档位（自动 / 强制硬解 / 强制软解）**都在 Media3 内部实现**，不再借 LibVLC 软解；
- 出错时不再提示"改用另一个内核续播"（没有别的内核可退）；
- LibVLC 那个「上次切过去 App 直接退出了」的确认框随之消失。

## 设置页重排（R21）

设置页是"一张一张卡片攒出来的"，攒到现在有三处不好用，这版一次理顺：

- **按使用频率分组**，从上到下：**连接 → 播放与后台 → 网络与缓存 → 更新 → 安全与凭据 → 诊断与日志**。
  常用的在上面，排障类的垫底。
- 每组一行**小标题 + 一句说明**，整行可点**折叠**；**「诊断与日志」默认折叠**（它是排障用的，平时不用看）。
- 原来那张「网络切换策略」卡里塞了 4 条**不同主题**的说明（选路 / 缓存 / 凭据 / 协议）——
  现在**说明贴在它解释的那一组里**，不再单开一张卡。
- 没有任何内容的组**不会显示空标题**。

## 新：自研引擎第一次能在界面里点到

- 播放页右上角「内核」按钮从**两档互切**改成**三档轮转**：
  **Media3 → 自研引擎 → LibVLC → Media3**（LibVLC 已知跑不了时自动跳过它）。
- 「自研引擎」＝自己写的播放内核（C++17 + 自研 FFmpeg + AAudio），
  数据走我们自己的数据层 ⇒ **本地 / SAF / WebDAV / SFTP / FTP 是同一条路**。
- 切过去之前会先弹一句说明（**不做静默降级**）：自研引擎目前还**没有倍速与硬解档位**；
  缩放四档、音量（含 >100%）、外挂字幕、拖拽调进度都正常。当前倍速不是 1.0× 的话，切过去会**如实回到 1.0×**。
- **自检不过就不让切**：自研引擎的启动自检跑在**独立进程**里（真开一次解码器 + 音频流），
  崩了只带走探针自己；没过就在播放页拦住并给「重新测试」。
- **播不了会自动换回来**：自研引擎遇到播不了的文件，会**自动切回 Media3 继续播**，并弹一句说明（不用你动手）。
- **默认内核仍是 Media3**：日常照常用，自研引擎这一档目前是"可试"。

## 新：诊断卡能看到播放指标

设置页「诊断与日志」组里新增两行：

- `自研引擎探针：通过（FFmpeg 7.1；解码 h264/aac 正常；音频 48000 Hz/2 声道正常）`
  —— 或没通过的原因；
- `最近播放：21:14:03  自研引擎：起播 380 ms · seek 等待 120 ms · 丢帧 0 · 音频欠载 0 · 音画偏差 -12 ms`
  —— **起播多快、卡没卡、音画偏多少**，一眼能看到，也能复制/另存/分享发我。

## 顺带（0.1.64 之后攒的）

- **列表封面空闲预热**：打开目录先等 3 秒（多半还在翻），再按并发 2 慢慢把视频开头封面取回来，取到就刷新那一格。
- **打开文件夹自动缓存**：进目录后台预取，单文件按段并发 4，一次 2 个文件，用户一操作就让路。

## 已知限制（自研引擎这一档）

- **没有倍速**（要改音频与时钟一起改，M5）；
- **没有硬解档位**（现在只有 FFmpeg 软解；硬解要 MediaCodec，等这一档在真机上验过再加，避免一次引入两个不可验证的变量）；
- 内嵌字幕轨还没做（外挂 srt/vtt/ass 正常，由 App 覆盖层渲染，与内核无关）；
- 画中画 / 后台播放 / 通知栏控制沿用既有会话层，行为与旧内核一致。
