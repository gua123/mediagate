# 0.1.76 发布说明

> 本版能感觉到的改动如下（字幕整条移除 + 之前攒下的一批）。
> 0.1.76 能感觉到的：**网络加载更快、回拖更顺**、**预约缓存只温开头了**、**预约缓存有前台服务了**、**包瘦了一圈**、**字幕整条去掉**、**边看边预取**（滑窗 + 下一集预热）、缓存的事都在一页里：**添加文件夹到队列**（含挑文件夹页）、**缓存明细**、**预约批量**、**点一下就预取**、**通知栏的媒体通知**、**只有一个播放内核**。

## 修：点了「自研引擎」切不过去（真机 0.1.66 实测）

真机现象：点内核轮到「自研引擎」，画面立刻退回 Media3，面包屑写着
`切换内核失败：自研引擎 → Failed to resolve SessionToken for ComponentInfo{…VideoPlaybackService}`。

两条根因，都修了：

1. **清单少了会话 action**：视频后台播放服务（`VideoPlaybackService`）在清单里没声明
   `androidx.media3.session.MediaSessionService`——Media3 的 `SessionToken` 靠这个 action 反查服务**类型**，
   查不到就抛异常。音频那个服务一直有，视频这个从 M8-A 起就没有（所以视频通知栏/锁屏控制其实一直没连上）。
2. **附属失败被当成内核失败**：换内核那条路没兜住这个异常 ⇒ 自研引擎被判成「播不了」⇒ 自动回退 Media3。
   现在兜底收在 `bindSession` 一处（起播/换集/换内核全部覆盖）：**会话连不上只记日志与面包屑，绝不影响播放**。

顺带加的护栏（都实证过「破坏就能红」）：清单与源码的交叉检查（凡是 `SessionToken` 按组件连的服务，
清单里必须有会话 action）、以及一条单测钉住「会话绑不上也要换内核成功」。
还修了一个**护栏假绿**：Gradle 原来判定测试「最新」会直接跳过（清单不是测试输入），现在清单与 res 已声明成输入。

## 改：网络加载提速（借鉴 nPlayer 的块级缓存思路）

你反馈「同样协议与网络，nPlayer 加载快一倍，已看过的部分回拖不卡」。对照它的缓存实现后，改了三处：

- **块级可见**：以前要**整段 4 MB 下完**才开始读，现在**写到哪块就能读哪块**——
  拖动落点只等第一块（64 KiB）而不是 4 MB，起播与回拖都更快；
- **预读从 2 段加到 4 段**（16 MB），并复用文件句柄，不再每次读都开关文件；
- **后台预取更积极**：滑窗预取一次排 **4 段、2 个连接并发**（原来每 20 秒只补 1 段），
  落点预取也并发两段；仍然遵守「预取给播放让路」（同一段不重复下载）。

说明：这次是**先按逆向出来的设计改**，具体并发数/段大小还要靠你真机对比（服务器可能限流）。
如果还差，下一步可以再调段大小（1/2/4/8 MB）与并发连接数——这些都在设置里有档位。
## 改：预约缓存只缓存开头一段（不整份下载）

按你说的「加载开头一段时间的缓存，而不是缓存该文件的全部，以提高初次打开时的观看体验」：

- 预约缓存现在只缓存**文件开头 12 MB**（小文件按整份），下完就标记完成，**不再整份下载**；
- 目的就是**初次打开快**：起播要读的文件头已经在本地，后面的内容照旧按需取（播放时的滑窗预取本来就在做）；
- 开头缓存按普通缓存参与 LRU（**不再逐个固定**）——几十个文件也不会把缓存空间与固定额度占满；
- 队列页与通知栏进度改成相对「要缓存的那一段」，例如「8.0 MB / 12 MB（67%）」，并在队列页加一句说明；
- 下载仍是后台服务（0.1.74 已加）：切走、息屏继续，通知栏有进度与暂停/继续，杀进程后自动续。

## 新：预约缓存变成真正的后台下载

按你说的「需要加前台服务」：

- 点了「加入队列」之后，**切到别的 App、息屏都会继续下**（前台服务，dataSync 类型）；
- 通知栏有一格**进度**：「正在缓存视频 · 第 2/5 个 · 45% · 文件名」，带**暂停 / 继续**按钮；
- 队列空了它自己退场，不留一个空转的通知；
- **进程被杀也不怕**：待处理项落盘，下次打开 App 自动接着下（已下好的段与手动缓存标记都还在）；
- 规则没变：播放视频时自动让路、手动预约的文件不会被自动清理。

## 改：把已下线引擎的东西整个删掉（包瘦身）

按你说的「全部清理掉」：

- 删除自研引擎模块（含它自带的两份 FFmpeg 原生库）与 LibVLC 引擎代码；
- 删除回环 HTTP 代理模块（只服务 LibVLC）——伪地址编解码搬进引擎模块，行为不变；
- 删除两个独立进程探针（:vlcprobe / :engineprobe）与它们的结论判定、诊断卡那一行；
- 删掉配套的设置键、面包屑启发式与对应单测；
- **APK 从 87 MB 收到约 24 MB**（少掉的是自研引擎自带的两份 FFmpeg 原生库），包内不再有 libvlc / 自研引擎库。

保留：EngineKind 里的历史枚举值（解析旧偏好用，读不到就回落 Media3）与播放页里那几条已不可达的引擎/探针分支
（播放页只认 Media3，这些入口不会出现；后续再单独做纯代码瘦身）。
## 改：字幕功能整条去掉

按你说的「**将字幕部分删除吧**」：

- 播放页**没有字幕按钮、没有字幕面板**了（原来的字幕开关 / 轨道选择 / 字号颜色描边 / ±0.5 秒微调 / 写回另存，全部移除）；
- 打开视频**不会再去找同目录的字幕文件**（.srt / .vtt / .ass 一律不再加载、不再覆盖显示）；
- 引擎侧的字幕轨装配也一起删了（Media3 的外挂轨配置、LibVLC 的 slave 与延迟）；
- 浏览器里点 .srt 这类文件会给「不支持」的提示（文件类型识别保留，只是不再有对应播放能力）；
- 数据库与其它功能一律不动：连接密码、断点、缓存、封面都还在。

## 改：边看边把"后面那点"和"下一集"先拿到本地（网络加载 P1）

接着上一版「点一下就预取」继续往前推：

- **滑窗预取**：看着的时候，每往前走 20 秒才发一次，只抓**当前位置往后 30 秒**那一段——
  往前小拖一点就落在本地，不用再等网络；快播完（距末尾不到 10 秒）就不抓了，文件大小拿不到时什么都不做；
- **下一集预热**：播到 **80%** 时，按**列表里的顺序**（和你看到的下一行一致）把**下一集的头尾两段**悄悄拉下来——
  连播切集因此几乎不用等。每个文件只预热一次，切走就重置。

两条都**给播放让路**（预取和播放要同一段时是同一个下载任务，不会重复下、也不会让播放排队）。

顺带说明两件**我判断后决定不做**的事（理由写进方案文档了）：① "先解析 MP4/MKV 索引再按索引取"——moov/cues 是 Media3 在解析，
我们这层按位置换算偏移已经等价，再往前要自己写容器解析器，**只为一个往返的收益不抵成本**；② "显式请求优先级队列"——
分段缓存本来就是按段单飞，播放与预取同一段是同一个任务，再加一层优先级等于给同一个保证写第二份实现。

## 改：缓存的事都在一页里办

按你的要求：「**将添加文件夹进队列和清理缓存界面放到一块**」。

**设置 →「网络与缓存」→「查看缓存明细」**这一页现在从"看"变成了"管"：

- 顶部新增「**添加文件夹到队列**」→ 进去就是一个**只列文件夹**的挑选页：点文件夹进下一层，
  每行右边「加入队列」＝把它里面的视频（含子目录）排上队；下面还有一句「把当前这个文件夹加进队列」；
- 同一页里接着就是**缓存队列**（进度、暂停/继续/取消）、**已缓存的文件**（含单条删除、取消固定）、**清空全部**。

浏览页的**长按加队列也保留**（正好在看着某个文件夹时更顺手）——两条路走的是同一套统计与确认逻辑，不会出现两处不一致。

## 新：预约缓存（在家一次点好，出门直接看）

按你的要求：「**增加手动批量多个文件的缓存方式，可以让我不打开对应文件夹就可以缓存视频**」。

- **在浏览页长按一行**：长按**视频** → 缓存这个视频；长按**文件夹** → 它会**递归统计里面的所有视频（含子目录）**，
  弹一句「将缓存 N 个视频」，点「加入队列」就开始下——**整个过程不用进那个文件夹**；
- **队列在后台按顺序下**，一次一个文件，**播放时会自动让路**（你看片的时候它不抢带宽，看完了自己接着下）；
- **进度看得见**：设置 →「网络与缓存」→「查看缓存明细」，最上面就是「缓存队列」（进行中/排队/已完成/失败 + 百分比），
  可以**暂停 / 继续 / 逐条取消 / 清掉已结束**；
- **手动缓存的文件不会被自动清理**：它们被"固定"住了，缓存上限到了也不会把你自己点的东西淘汰掉
  （明细里标着「手动缓存（不会被自动清理）」，旁边可以「取消固定」把它交回自动管理）；
- 长按不是视频（比如字幕、图片）会给一句说明，不会静默什么都不做。

**v1 的两条边界（如实说）**：① 队列在内存里——**杀进程后队列会丢**（已下好的部分和"固定"都还在，重新长按一次就会续着下）；
② 下载期间没有单独的通知，App 被系统回收时下载会停。这两条要做就得加前台服务（下一步可加）。

## 新：缓存明细（能看到哪些文件缓存过了）

你问的「能不能加个界面告诉我哪些缓存过、哪些没有」——**设置 →「网络与缓存」→「查看缓存明细」**：

- 一行一个已缓存的文件：**文件名** + 「已缓存 8.0 MB · 2 段 · 占该文件 8%」+ 完整路径（小字，便于对上号）；
- 头部合计：「已缓存 3 个文件 · 合计 42.5 MB」+ 当前缓存上限；
- 每条右边有**删除**（只清这个文件的段）；顶部有**清空全部**；
- 老版本留下的缓存（那时还没记录文件名）会显示成「旧版本缓存，名称未知」，但一样能删。

说明两点：**没在列表里的文件就是还没缓存过**（远端文件打开过才会按段落到本地）；总大小拿不到时不显示百分比（宁可空着也不瞎算）。

## 修：通知栏一直没有它（视频后台播放的媒体通知）

反馈原话：「**现在点开有封面的视频快了很多，这很好，但是通知栏还是没有**」。

- **根因**：点视频时**从来没申请过通知权限**（音频那条路一直在申请，视频漏了）——
  而 Android 13 以后没有这个权限，系统**什么通知都不显示**，媒体通知也一样；
- 现在点视频会和点音频一样先申请一次；
- 顺带把这条链路的**自述**放进设置页诊断卡：「视频会话：控制器 已连接 · 会话源 有（片名）· 通知权限 已授予」——
  通知栏不出现有三条互相独立的链路（权限 / 会话控制器 / 会话源），这一行能直接指出是哪一条断了。

## 改：上 G 的视频，第一次点开不用等那么久了

按你的反馈：「**针对上 G 大小的视频文件进行特殊缓存优化，现在文件第一次点还是会等待时间比较久**」。

- **点一下就开抓**：以前要等播放页起来才开始预取（那时播放器已经在要数据了），现在**手指点下文件的那一刻**就发出去——
  从"点下"到"播放器发第一条请求"之间还有几百毫秒，这点时间正好省掉一个网络往返（你那条链路一次往返 ≈0.6 秒）；
- **大文件多抓一点**：超过 1 GB 的文件，开头一次抓 3 段（大文件的索引和第一个关键帧常常不在第一段里），
  外加最后一段（MP4 的 moov、MKV 的 cues 一般都在文件末尾）和你的续播位置；
- **不影响播放**：预取永远给播放让路，同一段不会重复下载；文件大小拿不到时**什么都不做**（不瞎猜位置）。

## 改：播放内核回到原来那一个（自研引擎与 LibVLC 下线）

按你的要求：「**画面全没有，所以我想切回原先的引擎，将自研引擎和 libvlc 都去掉吧，原有引擎就可以。**」

- 播放页**不再有右上角那个「内核」按钮**（只剩一个内核，没什么可切的）；
- 旧版本里存过的内核偏好（LibVLC / 自研引擎）会**自动回到 Media3**，不会因此打不开；
- 三种解码档位（自动 / 强制硬解 / 强制软解）**都在 Media3 内部实现**，不再借 LibVLC 软解；
- 出错时不再提示"改用另一个内核续播"（没有别的内核可退）；
- LibVLC 那个「上次切过去 App 直接退出了」的确认框随之消失。

## 设置页重排（R21）

设置页是"一张一张卡片攒出来的"，攒到现在有三处不好用，这版一次理顺：

- **按使用频率分组**，从上到下：**连接 → 播放与后台 → 网络与缓存 → 更新 → 安全与凭据 → 诊断与日志**。
  常用的在上面，排障类的垫底。
- 每组一行**小标题 + 一句说明**，整行可点**折叠**；**「诊断与日志」默认折叠**（它是排障用的，平时不用看）。
- 原来那张「网络切换策略」卡里塞了 4 条**不同主题**的说明（选路 / 缓存 / 凭据 / 协议）——
  现在**说明贴在它解释的那一组里**，不再单开一张卡。
- 没有任何内容的组**不会显示空标题**。

## 新：自研引擎第一次能在界面里点到

- 播放页右上角「内核」按钮从**两档互切**改成**三档轮转**：
  **Media3 → 自研引擎 → LibVLC → Media3**（LibVLC 已知跑不了时自动跳过它）。
- 「自研引擎」＝自己写的播放内核（C++17 + 自研 FFmpeg + AAudio），
  数据走我们自己的数据层 ⇒ **本地 / SAF / WebDAV / SFTP / FTP 是同一条路**。
- 切过去之前会先弹一句说明（**不做静默降级**）：自研引擎目前还**没有倍速与硬解档位**；
  缩放四档、音量（含 >100%）、外挂字幕、拖拽调进度都正常。当前倍速不是 1.0× 的话，切过去会**如实回到 1.0×**。
- **自检不过就不让切**：自研引擎的启动自检跑在**独立进程**里（真开一次解码器 + 音频流），
  崩了只带走探针自己；没过就在播放页拦住并给「重新测试」。
- **播不了会自动换回来**：自研引擎遇到播不了的文件，会**自动切回 Media3 继续播**，并弹一句说明（不用你动手）。
- **默认内核仍是 Media3**：日常照常用，自研引擎这一档目前是"可试"。

## 新：诊断卡能看到播放指标

设置页「诊断与日志」组里新增两行：

- `自研引擎探针：通过（FFmpeg 7.1；解码 h264/aac 正常；音频 48000 Hz/2 声道正常）`
  —— 或没通过的原因；
- `最近播放：21:14:03  自研引擎：起播 380 ms · seek 等待 120 ms · 丢帧 0 · 音频欠载 0 · 音画偏差 -12 ms`
  —— **起播多快、卡没卡、音画偏多少**，一眼能看到，也能复制/另存/分享发我。

## 顺带（0.1.64 之后攒的）

- **列表封面空闲预热**：打开目录先等 3 秒（多半还在翻），再按并发 2 慢慢把视频开头封面取回来，取到就刷新那一格。
- **打开文件夹自动缓存**：进目录后台预取，单文件按段并发 4，一次 2 个文件，用户一操作就让路。

## 已知限制（自研引擎这一档）

- **没有倍速**（要改音频与时钟一起改，M5）；
- **没有硬解档位**（现在只有 FFmpeg 软解；硬解要 MediaCodec，等这一档在真机上验过再加，避免一次引入两个不可验证的变量）；
- 内嵌字幕轨还没做（外挂 srt/vtt/ass 正常，由 App 覆盖层渲染，与内核无关）；
- 画中画 / 后台播放 / 通知栏控制沿用既有会话层，行为与旧内核一致。
