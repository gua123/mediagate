## mediagate 0.1.33

### 从你截图里读到的：失败提示"看不出下一步"

你那张「新建连接」截图上，结果是：

```
〔使用：本次新输入的密码〕测试失败：
http://vpn.gua233.top:20005 — 未知错误 · 查看详情
（DNS 209 ms · TCP 1 ms · 握手 579 ms）
```

颜色这回是对的（失败=红 ✓），但「**未知错误 · 查看详情**」等于什么都没说。查了一下：

- **HTTP 3xx（跳转）与 5xx（服务端错误）以前没有分类**，全都落进"未知错误"；
- 分类不出来时，界面也**不显示原始原因**，只留一句"查看详情"。

### 这一版改了什么

1. **补上三类能照做的失败**：
   - **服务器要求跳转**（3xx）：提示"换 https 试试，或用跳转后的地址（也可能是反代配置）"；
   - **服务器内部错误**（5xx）：提示"服务端/反向代理的问题：看服务日志或稍后重试"；
   - **请求被服务端拒绝**（400/429 等）：提示"换根路径或换个地址试试（也可能被限流）"；
2. **实在分不出来时，把原始原因摊开**：显示「（原始原因：…）」或「（卡在协议握手，服务端没给出可识别的原因）」；
3. 顺手把「未知错误 · 查看详情」的提示语改成「看后面括号里的原始原因」。

### 关于你这个地址，我在本机替你探了一下（只发了匿名请求，没带任何凭据）

| 请求 | 结果 | 说明 |
| --- | --- | --- |
| `GET http://vpn.gua233.top:20005/` | **404**（`Server: Apache`） | WebDAV 根目录对普通 GET 返回 404 是正常的 |
| `PROPFIND http://vpn.gua233.top:20005/`（匿名） | **401** | **说明这个端口确实是 WebDAV，只是在要认证** ✅ |

也就是说：**地址和端口是对的，服务也在**。失败大概率出在认证或根路径上——装了这一版之后，
再点一次「测试一下」，它会**直接告诉你**是认证失败（401）、路径不对（404）还是别的什么。
